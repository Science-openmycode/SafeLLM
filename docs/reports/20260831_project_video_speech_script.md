## 三、可直接照读的演讲稿

### 00:00–00:20　开场

【画面：部署总览顶部，不滚动】

大家好，下面演示我们的隐私保护大模型推理系统“隐变智模”。它解决的是一个很具体的问题：用户拥有自己的私有模型和敏感提示词，但希望使用云端 GPU 算力，又不希望云端服务器直接获得原始模型参数、用户问题和最终答案。

### 00:20–00:50　应用场景

【画面：应用场景框架】

这个场景中，左侧是模型所有者，右侧是提供算力的云端服务器。服务器按照协议完成推理，但我们按照“诚实且好奇”的威胁模型，认为它可能观察模型、请求和运行过程。

因此，用户首先在本地对原始模型进行一次离线改造，再把改造后的模型部署到云端。在线推理时，发送的是受保护的请求，云端返回的也是受保护的结果，只有可信边界和客户端能够恢复真实语义。

### 00:50–01:20　总体技术路线

【画面：总体技术路线图】

整个系统分成离线和在线两部分。

上半部分是一次性的模型改造：原始模型经过精确重参数化，生成可直接部署的私有模型包。模型结构以及 PyTorch、Transformers 和 CUDA 推理框架不需要侵入式修改，因此仍然可以使用常见的部署方式。

下半部分是在线隐私推理：客户端和可信边界负责保护输入与恢复输出，云端 GPU 负责最重的 Transformer 计算。这样既利用云端算力，又不把普通提示词和普通回答直接暴露给云端模型主体。

### 01:20–01:50　模型适配与部署能力

【操作：进入“模型”，展示模型族；再进入“已部署模型”】

产品已经把模型改造、下载、部署和版本管理整合到一个桌面程序中。模型目录按照架构族组织，目前可以看到 Qwen、DeepSeek、GLM、Kimi 等系列，以及不同参数规模。

这里用于演示的是 Qwen2.5-0.5B 的 TEE 国密模式。它已经部署到本机并通过健康检查。真实生产部署时，可以把模型主体部署到云端 GPU，并由受证明的 TEE 承担可信边界。

### 01:50–02:10　用户体验

【操作：在已部署模型中点击“启动对话”】

对最终用户来说，使用方式和普通大模型一致：输入自然语言问题，获得正常回答，可以连续多轮对话。区别在于提示词、模型中间状态和回复 Token 在进入不可信边界前后，都经过了相应的保护和恢复。

下面打开隐私原理页面，看一次推理到底发生了什么。

### 02:10–03:05　TEE 推理主线

【画面：TEE 推理主线图；鼠标依次指向入口、中间、出口】

首先看入口。客户端在本地完成分词，并通过国密安全通道发送加密 Token。TEE 验证并解密后，用普通 Token ID 查询受保护的 Embedding，得到私有坐标下的初始隐藏向量。离开 TEE、交给 GPU 的已经不是普通 Token，也不是普通 Embedding。

第二步是中间计算。GPU 只接收私有隐藏向量、私有 KV Cache 和经过改造的模型权重，并运行完整的 Transformer 主体。每一层都在对应的私有坐标中计算，GPU 最终返回的仍然是私有隐藏状态。

第三步是出口。TEE 恢复最终隐藏状态，执行 LM Head 的安全计算、校验和采样，得到普通 Token ID。大矩阵乘法可以通过掩码后外包给 GPU，TEE 再去除掩码并校验结果，GPU看不到真实隐藏向量和真实 logits。

如果该 Token 不是结束符，它会在 TEE 内再次查询 Embedding，与 KV Cache 一起进入下一轮 Decode；同时这个 Token 通过国密通道加密返回客户端，由客户端增量解码。这样就形成完整的生成自循环。

### 03:05–04:35　运行一次，展示真实数据

【画面：“运行一次，看实际数据如何变化”；问题提前填好】

现在我们实际输入一句“请用一句话说明北京是什么地方”，运行一次完整推理。页面展示的不是预先写好的示意值，而是这次运行产生的核心数据。

【点击运行；等待期间继续讲，不要停顿】

整个过程分为五步：客户端加密发送、TEE 解密并查询 Embedding、GPU 完成 Transformer 主体、TEE 与外部 Head 完成安全矩阵计算，最后把结果返回客户端并进入下一轮自循环。

【完成后按 1 到 5 依次滚动】

第一步可以看到普通 Token 序列只保留在可信侧，网络上出现的是 nonce、密文和认证标签。

第二步，TEE 解密出 Token，并计算初始隐藏向量。这里展示了向量形状和真实数值样本，交给 GPU 的是私有坐标向量。

第三步，GPU 经过 24 层 Transformer 得到新的私有隐藏状态，同时维护私有 KV Cache。输入和输出形状相同，但具体数值已经经过模型计算发生变化。

第四步，TEE 恢复有效隐藏状态，对外包 Head 输入加掩码；GPU只完成大矩阵乘法，TEE去掩码并执行两轮 Freivalds 校验，随后采样得到普通 Token ID。

第五步，这个 Token 被加密返回客户端，客户端恢复出“北京”；同一个 Token 又在 TEE 内进入下一轮 Embedding 和 Decode，直到生成结束。

### 04:35–05:05　安全边界

【画面：安全增强与边界】

这里需要明确安全边界。云端 GPU 可以观察运行长度、时序、私有权重、私有隐藏状态和 KV Cache，但不能直接看到普通 Token、普通 Embedding、真实 logits、边界密钥和最终普通答案。

基础方案保护单次推理和模型主体；面对长期、多轮查询，还可以增加噪声级增强或机密级拆分与 TEE 保护。演示中的完整数据闭环已经实现；生产环境的硬件级安全结论，需要由 Intel TDX 远程证明和对应测量值共同保证。

### 05:05–05:35　回到对话展示最终效果

【操作：返回对话，打开“显示隐私过程”，发送同一个问题】

回到对话页面，我们再次发送问题。用户看到的仍然是正常答案；展开隐私过程后，可以同时看到网络上的加密提示词和加密回答。普通文本只在客户端和可信边界内出现，不会作为明文进入 GPU 模型主体。

### 05:35–05:50　性能与总结

【画面：隐私轨迹底部的 TTFT、TPOT、吞吐与完成状态】

页面同时记录首 Token 延迟、Token 生成间隔、总耗时和输出速度，用于量化隐私保护带来的额外开销。

总结来说，隐变智模完成了从模型改造、一键部署、可信边界，到真实隐私推理和结果恢复的完整链路。它让用户继续使用云端 GPU 算力，同时把模型、提示词和回答限制在可控的安全边界中。谢谢大家。

## 四、重新录制时的操作清单

1. 录制前确认麦克风轨道已开启，并先录 10 秒测试语音。
2. 把演示问题提前复制到剪贴板，避免现场输入和中文候选框停顿。
3. 开始录制前确保部署模型已经是 `HEALTHY`，隐私原理页面已经完成首次加载。
4. 总览只向下滚动一次，不要在应用场景与总体路线之间来回移动。
5. 模型目录只展示一个模型族，不逐个点击型号。
6. 已部署模型只指出本次演示模型，避免观众被其他历史部署分散注意力。
7. “运行一次”点击后不要沉默，用五步概览填充等待时间。
8. 数据出现后，每一步至少停留 6–8 秒，鼠标只指向正在讲的字段。
9. 安全增强页控制在 30 秒，只讲可见、不可见和生产安全依据。
10. 最后的加密提示词、加密回答和性能指标至少保留 20 秒。
