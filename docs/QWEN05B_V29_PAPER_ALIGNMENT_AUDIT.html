2. 原文要求的完整数据流

2.1 客户端输入

客户端持有原始 tokenizer、词表置换 τ\tau 和逆置换 τ−1\tau^{-1}。对明文 prompt 应用 Chat Template 后得到原始 token：

s=(t1,t2,…,tn). s=(t_1,t_2,\ldots,t_n).

默认隐私模式直接置换每个 token ID：

s̃=τ(s)=(τ(t1),τ(t2),…,τ(tn)). \widetilde{s}=\tau(s) =(\tau(t_1),\tau(t_2),\ldots,\tau(t_n)).

原文第 5.3 节要求先把 s̃\widetilde{s} 解码成“混淆文本”，服务端再分词。该等式要求

Encode⁡(Decode⁡(s̃))=s̃, \operatorname{Encode}(\operatorname{Decode}(\widetilde{s}))=\widetilde{s},

但 Qwen tokenizer 对任意置换 ID 不满足这个条件。因此产品接口直接发送 s̃\widetilde{s} 的 token ID，避免混淆文本重分词破坏序列。

2.2 Embedding 和词表

原始 Embedding 为 We∈ℝ|V|×dW_e\in\mathbb{R}^{|V|\times d}。原文先加入高斯噪声：

We*=We+αeEe,(Ee)ij∼𝒩(0,σe2), W_e^*=W_e+\alpha_e E_e, \qquad (E_e)_{ij}\sim\mathcal{N}(0,\sigma_e^2),

其中 σe\sigma_e 是原始 Embedding 权重的标准差。再使用词表置换矩阵 Π\Pi 和扩维矩阵 PP：

W̃e=ΠWe*P. \widetilde{W}_e=\Pi W_e^*P.

代码采用 HF 的行存储方向，等价操作是先计算 weight @ P，再把原始词表行移动到 tau[plain_id] 对应的私有行。

2.3 Algorithm 1：从 dd 扩展到 d+2hd+2h

代码按原文构造

B=U+λV, B=U+\lambda V,

并生成共享的 B,E,F,ZB,E,F,Z。修正后的矩阵为

P=[BCE]Z, P=[B\;C\;E]Z,

Q=Z⊤[B−1FD], Q=Z^\top \begin{bmatrix} B^{-1}\\ F\\ D \end{bmatrix},

其中必须满足

CF=0,ED=0. CF=0, \qquad ED=0.

于是

PQ=BB−1+CF+ED=Id. PQ=BB^{-1}+CF+ED=I_d.

原文把 CC 和 DD 的“行/列属于哪个零空间”写反，按原句无法满足矩阵维度。实现使用可计算且能证明 PQ=IdPQ=I_d 的解释：CC 的每一行位于 null⁡(F⊤)\operatorname{null}(F^\top)，DD 的每一列位于 null⁡(E)\operatorname{null}(E)。

2.4 Attention

进入 Attention 前，私有 residual 为

z=xP. z=xP.

每个输入投影使用与同一 PP 兼容的右逆：

PQq=PQk=PQv=Id. PQ_q=PQ_k=PQ_v=I_d.

在 HF 权重方向下，基础投影变换为

W̃q=WqΓQq⊤,W̃k=WkΓQk⊤,W̃v=WvΓQv⊤, \widetilde{W}_q=W_q\Gamma Q_q^\top, \quad \widetilde{W}_k=W_k\Gamma Q_k^\top, \quad \widetilde{W}_v=W_v\Gamma Q_v^\top,

其中 Γ\Gamma 是融合进投影的原始 RMSNorm 权重。

Algorithm 2 对每个 KV 组构造 Q/K 变换：

Tq=RqkHqkZblock,Tk=RqkHqk−1Zblock, T_q=R_{qk}H_{qk}Z_{block}, \qquad T_k=R_{qk}H_{qk}^{-1}Z_{block},

因而在不发生错误 RoPE 频率置换时：

TqTk⊤=I. T_qT_k^\top=I.

V/O 使用高斯矩阵 UvoU_{vo} 和逆矩阵：

v′=vUvo,Wo′=Uvo−1WoP. v'=vU_{vo}, \qquad W_o'=U_{vo}^{-1}W_oP.

Qwen2.5-0.5B 有 14 个 Q head、2 个 KV head，每个 KV head 对应 7 个 Q head。实现同步置换 KV 组、对应的 7 个 Q/O head，并在每组内部置换 Q/O head。全量公式审核检查了 24 层的组对应关系。

2.5 FFN

对 SwiGLU 的 Gate、Up、Down 三个矩阵使用同一个中间维置换 ZffnZ_{ffn} 和同一组非零缩放 HffnH_{ffn}：

W̃gate=QgateWgateZffn, \widetilde{W}_{gate}=Q_{gate}W_{gate}Z_{ffn},

W̃up=QupWupHffn−1Zffn, \widetilde{W}_{up}=Q_{up}W_{up}H_{ffn}^{-1}Z_{ffn},

W̃down=Zffn−1HffnWdownP. \widetilde{W}_{down}=Z_{ffn}^{-1}H_{ffn}W_{down}P.

代码按 HF 转置存储执行同一组行置换、列置换和互逆缩放。原文没有给出随机缩放的概率分布；配置记录实际使用的对数均匀范围 [0.5, 2.0]。

2.6 RMSNorm 和 Residual

原文用标量

κ=𝔼[‖xP‖2‖x‖2] \kappa=\mathbb{E}\left[\frac{\lVert xP\rVert_2}{\lVert x\rVert_2}\right]

近似补偿 RMSNorm。但一般矩形 PP 会各向异性地改变向量，单个标量不能对每个输入精确恢复原 RMS。

v29 使用可验证的精确修正式。若 z=xPz=xP 且 PQ=IPQ=I，则

x=zQ, x=zQ,

RMS⁡(x)2=1dzQQ⊤z⊤. \operatorname{RMS}(x)^2 =\frac{1}{d}zQQ^\top z^\top.

服务端 checkpoint 因此保存派生度量

G=QQ⊤. G=QQ^\top.

两条 residual 支路始终保留在同一个 PP 坐标中；只有进入 Q/K/V、Gate/Up、LM Head 等投影时，才通过相应的兼容右逆恢复原坐标。

2.7 LM Head 和客户端输出

Head 噪声和变换为

Wh*=Wh+αhEh, W_h^*=W_h+\alpha_hE_h,

W̃h=ΠWh*ΓfQh⊤. \widetilde{W}_h=\Pi W_h^*\Gamma_fQ_h^\top.

服务端输出私有 token ID ỹi\widetilde{y}_i。客户端逐 token 计算

yi=τ−1(ỹi) y_i=\tau^{-1}(\widetilde{y}_i)

并使用原始 tokenizer 解码。对话历史、明文 prompt、τ\tau 和 τ−1\tau^{-1} 均留在客户端。

2.8 M1 和 Theorem 4

原文 Definition 2 在长度为 nn 的 token 序列空间上定义换位距离 d(x,x′)d(x,x')，M1 的分布为

pM1(x)(y)∝exp⁡{−ϵ1d(x,y)}. p_{M_1(x)}(y)\propto \exp\{-\epsilon_1 d(x,y)\}.

Theorem 4 的分段预算使用的是序列长度 nn，不是词表大小：

ϵ2=π2(ϵe+ϵh), \epsilon_2=\pi^2(\epsilon_e+\epsilon_h),

ϵ={ϵ1−ϵ124(n−1)ϵ2,ϵ1≤2(n−1)ϵ2,(n−1)ϵ2,otherwise. \epsilon= \begin{cases} \epsilon_1-\dfrac{\epsilon_1^2}{4(n-1)\epsilon_2}, & \epsilon_1\le 2(n-1)\epsilon_2,\\ (n-1)\epsilon_2, & \text{otherwise}. \end{cases}

本轮审核发现旧实现误把 vocab_size 代入了 nn。现已把正式接口改为 sequence_length / --sequence-length；旧 vocab_size 仅保留为会触发弃用警告的兼容别名。 M1 产品路径仍是长度 1 的精确机制逐 token 组合，不把它写成原文完整长度-nn 联合采样器。

8. 继续实现的边界

要把“当前功能工件”推进为“论文默认安全参数工件”，必须另建 checkpoint，不得覆盖 v29：

  1. 启用非零 αe,αh\alpha_e,\alpha_h，重新跑 200 prompt、完整精度任务和全部攻击；
  2. 将 paper-default 与 product 分开，不能用无噪声结果证明有噪声模型；
  3. BlockPerm 若坚持 β=8\beta=8，只能如实测量其精度损失；标准 Qwen RoPE 下不能同时声称它严格函数保持；
  4. 标量 κ\kappa 分支可以复现实验近似，但不能取代 exact-metric 产品分支的功能门禁；
  5. VMA、Gate-IA、TFMA 等有足够定义的攻击应绑定新 checkpoint 重跑；缺少公开协议的 IMA/SDA 和错误 Attn-IA 必须继续单列。

本报告对应的机器证据是 artifacts/verification/qwen05b-functional-v29/paper-alignment-audit.json。该文件绑定当前 checkpoint config、offline key、公式证据、逐层证据、200 prompt、运行时、隐私边界和 HTTP/SSE 结果的 SHA-256。
