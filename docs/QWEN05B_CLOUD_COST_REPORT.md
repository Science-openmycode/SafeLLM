## 📋 结论

| 方案 | 完成范围 | 预留实例小时 | GPU 小时 | GPU 费用 |
| --- | --- | ---: | ---: | ---: |
| RTX 4090 单机完整验收 | HF、攻击、精度、产品、vLLM、SGLang | 49 h | 49 h | ¥88.20 |
| RTX 3090 HF 正式验收 | 除 CUDA 13 引擎外的全部阶段 | 53 h | 53 h | ¥46.64 |
| RTX 4090 只补引擎 | vLLM、SGLang 兼容性 | 8 h | 8 h | ¥14.40 |
| 3090 + 4090 两机组合 | 完整证据，分机执行 | 61 h | 61 h | ¥61.04 |

推荐选择：

- **最省操作时间：** 一张驱动 580 的 RTX 4090 连续保留 49 小时，GPU 预算 `¥88.20`
- **最低 GPU 费用：** RTX 3090 跑 HF 主流程，再用 RTX 4090 补引擎，GPU 预算 `¥61.04`

两机组合省 `¥27.16`，但需要第二次上传、环境安装和工件回传。若由一个人执行且希望减少操作错误，
优先用 4090 单机方案。

本报告的小时数是**计费上限计划**，不是尚未发生的实测耗时。所有云端脚本会把每阶段实际秒数写入
`artifacts/cloud/qwen05b-v47/stage-timings.tsv`；实验结束后再计算真实账单。

## 💰 单机 RTX 4090 计划

实例输入：

```text
GPU: NVIDIA GeForce RTX 4090 24 GB
驱动: 580.159.04
单价: ¥1.80 / 实例小时
GPU 数: 1
计费粒度假设: 1 小时向上取整
```

逐阶段预算：

| 阶段 | 计划小时 | 执行入口 | 退出条件 |
| --- | ---: | --- | --- |
| 建机和数据盘 | 0.5 | 手工建机 | `/data` ≥ 90 GB 可用 |
| 上传和 SHA-256 | 0.5 | bundle verifier | 三包全部通过 |
| CUDA 12.1 核心环境 | 1.5 | `bootstrap_qwen05b_cuda121.sh` | preflight 全绿 |
| CUDA 13 引擎环境 | 2.5 | `bootstrap_qwen05b_engines_cuda13.sh` | 两个版本可导入 |
| 静态测试和模型验证 | 1.0 | `static`、`verify` | 测试通过、server 包净化 |
| 正式隐私攻击 | 9.5 | 攻击脚本八阶段 | 全部 score JSON 生成 |
| MMLU/C-Eval/PIQA | 6.0 | `accuracy-mc` | 17,226 题两侧完成 |
| IFEval 两侧 | 8.0 | `ifeval` | `541 + 541` 生成完成 |
| HumanEval 两侧 | 3.0 | `humaneval` | `164 + 164` 生成和执行完成 |
| 产品门禁 | 2.0 | `product` | 100 问和传输隐私完成 |
| HF 平衡性能 | 2.0 | `performance` | 80 对请求完成 |
| vLLM/SGLang | 3.0 | compatibility script | 三后端 token 对齐 |
| 最终验收和下载 | 1.0 | `acceptance`、打包 | 验收 JSON 和证据已回传 |
| **基础合计** | **40.5** |  |  |
| **20% 重跑准备金** | **8.1** |  |  |
| **按整小时预留** | **49.0** |  |  |

计算：

```text
基础小时 = 40.5 h
准备金 = 40.5 h × 20% = 8.1 h
未取整总小时 = 48.6 h
预留实例小时 = ceil(48.6 / 1.0) × 1.0 = 49.0 h
GPU 小时 = 49.0 h × 1 GPU = 49.0 GPU·h
GPU 费用 = 49.0 h × ¥1.80/h = ¥88.20
```

若平台按分钟计费而不是整小时计费，48.6 小时对应 `¥87.48`；本报告仍按更保守的 49 小时
预算执行。

## 🔍 小时依据与不确定项

### 已有本机观测

| 项目 | 本机观测 | 用途 |
| --- | ---: | --- |
| v47 VMA | 9,082.37 s = 2.523 h | 攻击阶段下限依据 |
| MMLU 私有侧完成窗口 | 约 3.53 h | 选择题私有侧依据 |
| C-Eval 私有侧完成窗口 | 约 0.32 h | 选择题依据 |
| PIQA 私有侧完成窗口 | 约 0.22 h | 选择题依据 |
| IFEval 本机早期样本 | 6 条约 13 min | 仅说明 6 GB 本机不适合全量 |

VMA 的 `9,082.37 s` 来自当前 `artifacts/privacy/v47/vma-predictions.json` 中记录的
`elapsed_seconds`。其余选择题使用连续工件完成时间估算，包含模型加载和可能的调度间隔，不能当作
精确 kernel 时间。云端预算没有直接按显卡理论算力缩放，而是保留了安装、数据、FP64 Attention
和失败重跑余量。

### 不计入 ¥88.20 的项目

| 项目 | 当前状态 | 处理方式 |
| --- | --- | --- |
| 数据盘从 50 GB 扩到 100 GB | 用户报价未给单价 | 下单页单列 |
| 公网流量 | 用户报价未给计费规则 | 下单页确认 |
| 域名和 TLS 证书 | 未给价格 | 域名另计；证书可用现有方案 |
| CCI3/MedDialog 获取 | 数据访问条件未完成 | 在开机前完成授权 |
| 人工值守 | 不属于云资源 | 不计入 GPU 费用 |
| 更大模型 | 不在本报告范围 | 另立预算 |

如果数据盘扩容或流量收费，最终总额为：

```text
最终费用 = GPU 费用 + 数据盘费用 + 公网流量费用 + 其他平台固定费
```

没有平台存储和流量单价时，不能把这些项目伪造为 `0`。下单前应把结算页截图或企业报价保存到
`artifacts/cloud/qwen05b-v47/billing/`。

### 实际费用

所有 Bash 入口通过 `run_timed` 记录每次运行，包括失败重跑。实验结束后执行：

```bash
.venv-qwen05b-cu121/bin/python scripts/summarize_cloud_runtime_cost.py \
  --timings artifacts/cloud/qwen05b-v47/stage-timings.tsv \
  --hourly-rate 1.80 --gpu-count 1 --billing-increment-hours 1.0 \
  --out artifacts/cloud/qwen05b-v47/actual-cost.json
```

输出包含：

- 所有阶段真实秒数
- 原始实例小时
- 向上取整后的计费小时
- GPU 小时
- 失败阶段数量
- 按给定单价计算的费用

计时文件只覆盖脚本运行时间。实例创建后等待上传、人工停顿和打包下载也会计费；最终报销应以平台
账单为准，并用 `actual-cost.json` 解释实验代码实际占用。

## ✅ 停机规则

达到以下任一条件立即停止新增 GPU 消耗：

1. preflight 任一硬件或输入检查失败
2. checkpoint manifest 或 server package 扫描失败
3. CCI3/MedDialog 未形成 `formal_corpus_complete=true`
4. 运行小时达到 40.5 h 时先审查剩余任务
5. 达到 49 h 硬上限仍未完成时关机并保存工件
6. 正式验收已生成且所有证据已下载

49 小时不是允许脚本无限重跑的额度。每次失败必须先读对应
`artifacts/cloud/qwen05b-v47/logs/<stage>.stderr.log`，修复后只重跑失败阶段。
