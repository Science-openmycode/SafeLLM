# 隐变智模“部署到本机”产品需求

## 1. 问题陈述

隐变智模当前将正式部署目标限定为远程Ubuntu GPU服务器。产品演示、功能检查和离线使用时，用户即使已经在本机完成私有模型改造，也必须准备远程服务器才能完整走通“部署—验收—对话”流程。

本功能增加“本机”正式部署目标。本机部署必须像远程部署一样经历部署准备、候选服务启动、健康检查、私有Token往返检查和正式启用，不能退化为直接打开模型或模拟回答。

## 2. 目标用户

- 需要在单台电脑上演示完整隐私推理流程的项目人员。
- 需要在上传云端前验证私有模型可加载、可生成、可停止和可恢复的技术人员。
- 不具备SSH服务器，但已经拥有可在本机运行的私有模型和在线密钥的用户。

## 3. 用户流程

### 3.1 本机部署

```text
打开“隐变智模部署”
→ 选择已经完成改造和校验的私有模型
→ 选择“部署到本机”
→ 确认本机资源与部署信息
→ 开始正式部署
→ 完成本机运行条件检查
→ 创建候选部署版本
→ 启动私有模型服务
→ 完成健康检查
→ 完成模型、密钥和私有Token往返检查
→ 将部署登记为HEALTHY
→ 出现在“已部署模型”
```

### 3.2 本机对话

```text
打开“隐变智模对话”
→ 在可用部署中选择一个本机部署
→ 直接连接本机模型服务
→ 本地应用Chat Template和Tokenizer
→ 本地执行Token置换
→ 模型服务生成私有输出Token
→ 本地执行逆置换和解码
→ 流式显示回答
```

远程部署和远程对话流程保持不变。远程部署仍使用SSH服务器；本机部署不要求用户填写SSH信息。

## 4. 用户故事

- 作为演示人员，我希望把已经改造好的私有模型正式部署到本机，以便在没有云服务器时演示完整产品闭环。
- 作为技术人员，我希望本机部署执行与远程部署相同的功能验收，以便在上传前发现模型、密钥或运行环境问题。
- 作为对话用户，我希望在部署列表中直接选择健康的本机部署，以便不配置SSH隧道也能进行真实问答。
- 作为运维人员，我希望可以停止、重新启动、升级、回滚和删除本机部署，以便验证完整的部署生命周期。

## 5. 功能需求

### 5.1 部署目标

1. “隐变智模部署”必须提供“部署到远程服务器”和“部署到本机”两个清晰、互斥的目标。
2. 选择本机后，不得要求填写SSH主机、端口、用户名、密码或私钥。
3. 本机目标必须显示本机CPU、内存、GPU、显存和可用磁盘检查结果。
4. 资源不足时必须在启动模型服务前停止，并明确显示不足项。

### 5.2 正式部署过程

1. 只有完成改造并通过包完整性检查的私有模型可以部署到本机。
2. 部署前必须重新检查模型文件、清单、模型标识和密钥标识。
3. 每次本机部署必须生成独立部署标识和不可变版本标识。
4. 新版本必须先作为候选服务启动；候选服务通过全部检查后才能成为当前健康版本。
5. 部署必须展示当前阶段、进度、成功状态或完整失败原因。
6. 重复点击部署不得创建重复运行任务。
7. 部署失败不得破坏同一部署原有的健康版本。
8. 部署成功后必须进入“已部署模型”列表，并明确标记为“本机”。

### 5.3 部署验收

本机候选版本正式启用前必须通过：

1. 服务进程存活检查。
2. 健康接口检查。
3. 当前模型标识和预期模型标识一致。
4. 当前密钥标识和预期密钥标识一致。
5. 私有Token输入和私有Token输出接口可用。
6. 使用本地在线密钥完成一次私有Token往返检查。
7. 服务端日志不包含明文问题、明文Token序列或在线密钥。

任一检查失败，部署状态必须为FAILED，不能进入HEALTHY。

### 5.4 生命周期管理

本机部署必须支持：

- 启动；
- 停止；
- 重新启动；
- 查看健康状态；
- 查看有限的运行日志；
- 使用新私有模型版本升级；
- 升级失败后恢复上一个健康版本；
- 删除部署记录和由该部署创建的本地运行文件。

删除本机部署时，默认不得删除原始模型、私有模型或在线密钥。

### 5.5 对话程序

1. “隐变智模对话”必须同时列出健康的远程部署和健康的本机部署。
2. 每个部署必须显示“本机”或“远程”标识。
3. 选择本机部署时不得要求SSH密码、私钥或建立SSH隧道。
4. 选择远程部署时继续使用现有SSH隧道流程。
5. 本机和远程部署必须使用相同的私有Token协议、流式输出协议、会话历史和隐私轨迹展示。
6. 本机部署停止、失败或模型与密钥不匹配时，对话输入必须禁用并显示具体原因。
7. 切换本机部署和远程部署时，已有会话继续绑定原部署；用户必须新建会话才能更换部署。

## 6. 非功能需求

### 6.1 安全

- 本机模型服务只能接受本机连接，不能因演示模式自动暴露到局域网或公网。
- 浏览器页面不能读取完整在线密钥。
- 模型服务不得记录明文问题、明文Token序列、完整私有Token流或密钥内容。
- 本机部署不得降低现有私有模型包检查标准。

### 6.2 可靠性

- 部署程序重启后必须恢复本机部署记录，并重新判断实际运行状态。
- 已停止的部署不得错误显示为HEALTHY。
- 服务异常退出后必须显示DEGRADED或FAILED，不得长期停留在HEALTHY。
- 本机部署和远程部署状态不得互相覆盖。

### 6.3 易用性

- 普通用户不需要理解SSH、Docker或端口配置即可完成本机部署。
- 默认自动选择可用的本机服务端口。
- 错误信息必须说明用户下一步应执行的操作。
- 本机部署必须沿用现有界面风格和进度展示方式。

## 7. 验收标准

使用当前Qwen2.5-0.5B私有模型完成以下验收：

1. 用户可以从一个已完成的本地转换任务选择“部署到本机”。
2. 部署程序完整显示准备、启动、健康检查、私有往返检查和正式启用过程。
3. 部署成功后出现在“已部署模型”，状态为HEALTHY并标记“本机”。
4. 对话程序能够发现该本机部署，且不弹出SSH凭据窗口。
5. 用户可以完成至少五轮真实流式问答，后续问题能够使用前文上下文。
6. 停止部署后，对话程序禁止继续发送消息；重新启动后可以继续新请求。
7. 创建新版本并人为制造启动失败时，原健康版本保持可用。
8. 回滚后健康检查和私有问答检查重新通过。
9. 抓取本机请求和扫描日志，不出现明文问题、明文Token序列和在线密钥。
10. 远程部署、SSH隧道和远程对话现有测试继续通过。

## 8. 成功指标

- 已有私有Qwen2.5-0.5B模型时，用户无需服务器信息即可完成本机正式部署。
- 从点击“部署到本机”到进入HEALTHY无需手工执行命令。
- 本机部署后的对话结果与同一私有模型直接运行结果一致。
- 本机目标的加入不改变远程部署和远程对话行为。

## 9. 不在本需求范围内

- 不把原始未改造模型作为正式本机部署。
- 不提供模拟回答或确定性假Token服务。
- 不把本机演示服务暴露到公网供他人访问。
- 不改变现有远程SSH部署协议。
- 不在本需求中增加新的模型架构适配器。
- 不处理无法装入本机CPU内存或GPU显存的模型。
