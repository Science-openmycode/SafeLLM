# 隐变智模 Windows 产品需求文档

文档版本：1.0  
产品名称：隐变智模  
技术命令标识：`yinbian`  
目标平台：Windows 10/11 客户端、Ubuntu NVIDIA GPU 服务器  
文档状态：待最终批准

## 1. 产品定义

隐变智模用于将受支持的开源大模型在客户本地改造为私有表示模型，再部署到客户指定的云端 Ubuntu GPU 服务器。客户在本地保管密钥；日常问答由本地客户端完成分词、Token 置换和输出恢复，云端只运行改造后的模型并处理私有 Token ID。

产品交付一个 Windows 离线安装包。安装后包含两个独立桌面程序和一套功能对等的命令行工具：

- **隐变智模部署**：模型选择、下载、结构检查、分片改造、服务器管理、上传、部署、健康检查、升级和回滚。
- **隐变智模对话**：连接已部署并健康的模型，完成多轮私有问答、会话管理和隐私流程展示。
- **`yinbian` CLI**：覆盖两个桌面程序的全部可执行能力，供技术人员、脚本和自动化系统使用。

旧名称 AloePri 仅作为代码迁移兼容信息存在，不出现在新用户界面、安装包名称、桌面快捷方式和新建工件中。

## 2. 目标用户

### 2.1 模型管理员

负责选择模型、准备本地资源、连接服务器、执行模型改造和管理多个部署。可以是企业技术人员，也可以是按照向导操作的普通用户。

### 2.2 最终问答用户

只使用隐变智模对话，不接触原始模型、离线主密钥和部署流程。只能选择管理员已经部署成功并授权到本机的模型。

### 2.3 自动化维护人员

通过 `yinbian` CLI 执行批量检查、转换、上传、部署、健康检查、日志导出、启动、停止和回滚。

## 3. 固定产品原则

1. 先部署，后聊天。未通过健康检查的模型不能出现在对话程序中。
2. 一个用户可以管理多个模型、服务器、密钥版本和部署。
3. 桌面程序与 CLI 使用同一任务和部署记录，不能各自维护独立状态。
4. 所有桌面操作必须存在功能对等的 CLI 操作。
5. 明文问题、明文 Token ID、明文对话历史、在线逆置换和完整置换表不得发送到云端模型服务。为实现多轮上下文，客户端可以把本地历史重新应用 Chat Template、分词和置换后，以私有 Token ID 发送。
6. 云端模型包不得包含在线密钥、离线主密钥、原始随机种子或原始模型权重。
7. 模型改造按分片执行，避免要求客户长期保存完整原始模型和完整私有模型的双份副本。
8. CPU 可以执行改造；存在 NVIDIA GPU 时允许自动加速。
9. 产品不使用“绝对安全”“不可破解”或“加密模型”等超出实测证据的表述。
10. 视觉风格继承现有聊天前端：浅色侧边栏、绿色品牌色、白色卡片、克制留白和统一状态反馈。

## 4. 完整用户流程

```text
安装隐变智模
→ 启动隐变智模部署
→ 选择推荐模型或导入同架构模型
→ 检查模型结构、许可证和本地资源
→ 选择“直接部署”或“仅在本地改造”

直接部署：
  → 添加并检查 Ubuntu GPU 服务器
  → 确认服务器资源警告
  → 确认改造参数和清理策略
  → 逐片下载、改造、校验和上传
  → 安装运行组件并启动模型服务
  → 完成健康检查

仅在本地改造：
  → 确认改造参数和清理策略
  → 逐片下载、改造、校验并保存完整私有模型
  → 后续添加并检查 Ubuntu GPU 服务器
  → 确认服务器资源警告
  → 上传已保存的私有模型
  → 安装运行组件并启动模型服务
  → 完成健康检查

两条流程汇合：
→ 将健康部署登记到隐变智模对话
→ 建立 SSH 安全隧道
→ 选择部署并开始多轮私有问答
```

用户可以在任意任务完成后关闭程序。再次启动时必须恢复任务、服务器、部署和进度，不要求从头执行。

产品提供两条明确流程：

- **直接部署（默认）**：先选择并预检服务器，再下载一个分片、改造、校验、上传私有分片并按策略清理明文分片。本地不要求保存完整私有模型。
- **仅在本地改造**：没有可用服务器时，把全部私有分片保存在本地；后续选择服务器后再执行上传和部署。本流程需要足够空间保存完整私有模型。

## 5. 隐变智模部署

### 5.1 首页

首页展示：

- 可用模型数量；
- 正在运行、暂停、失败和完成的转换任务；
- 已保存服务器及连接状态；
- 运行中、部署中、停止和故障的部署；
- 本地 CPU、内存、GPU、显存和磁盘摘要；
- 需要处理的警告和失败任务；
- “部署新模型”主入口。

首页不得自动开始下载、转换、上传或删除操作。

### 5.2 模型目录

模型目录包含：

- 经过验证的推荐模型；
- 可以通过结构指纹识别的同架构模型；
- 本地已有原始模型；
- 本地已有私有模型；
- 已停止支持或不兼容的模型记录。

每个模型条目显示：

- 模型名称、发布者、固定版本和来源链接；
- 参数量、架构族、权重格式和下载体积；
- Dense、GQA、MLA、MoE、MTP 等结构能力；
- 当前支持状态和最近一次验证版本；
- 本地转换所需磁盘、内存和预计时间区间；
- 推荐云端 GPU 数量、单卡显存、内存和磁盘；
- 许可证名称、链接和用户确认状态；
- 已知限制和不适用功能。

推荐模型可以由程序直接下载。第一版支持公开 Hugging Face 仓库；私有仓库允许用户临时输入访问令牌，令牌默认不保存，用户主动保存时进入本地加密凭据库。用户也可以输入 Hugging Face 模型地址或选择本地目录。导入模型必须先完成结构检查；模型名称相似不能替代结构检查。

第一版支持矩阵固定为：

| 模型或架构 | 产品状态 | 允许的最高阶段 | 普通用户可见性 |
|---|---|---|---|
| Qwen2.5-0.5B-Instruct | 已验证 | 下载、转换、部署、对话和验收 | 推荐模型 |
| OpenSeek-small-v1-SFT 现有真实 checkpoint | 已验证转换 | 转换与本地功能回归；通过真实运行时门禁后才允许部署和对话 | 高级模型 |
| 其他 Qwen2/Qwen2.5 同族模型 | 实验支持 | 结构检查、转换；完成该 checkpoint 的健康与问答门禁后可由用户确认部署 | 高级模型，带实验标记 |
| DeepSeek-V2-Lite-Chat | 实验支持 | 结构检查和转换；不登记为正式可聊天部署 | 高级模型，带实验标记 |
| DeepSeek-V3 官方配置与缩小 fixture | 开发验证 | 静态计划、MLA/MoE/FP8/MTP 覆盖测试 | 普通用户不可见 |
| 未识别架构 | 不兼容 | 只允许生成检查报告 | 导入时显示拒绝原因 |

“实验支持”不得在界面中伪装成已验证。实验模型只有在当前 checkpoint 完成转换完整性、运行时加载、私有 Token 往返和固定问答冒烟后，才可以由用户确认创建实验部署；该结果不提升整个架构族为“已验证”。

实验 checkpoint 的问答冒烟固定使用版本化 manifest，首版为 `experimental-checkpoint-smoke-v1`，包含 20 条问题：10 条中文普通问答、5 条英文普通问答、3 条数学题和 2 条代码生成题。manifest 记录每条输入、生成参数、原始 tokenizer 版本和 SHA-256，验收时不得临时替换样本。

每个实验 checkpoint 必须依次通过：

1. 无噪声转换在 20 条问题上使用 greedy、最多 32 个新 Token，与原模型逐 Token 完全一致；
2. 拟部署产品配置在同一 20 条问题上完成生成，空回答为 0；
3. 非法 Token ID、解码异常和首个非特殊 Token 前提前 EOS 均为 0；
4. 长度 1—8 的 Token 周期连续重复至少 4 次且占输出至少 16 Token 的循环回答为 0；
5. 客户端输入置换、服务端生成和客户端输出恢复的完整往返 20/20 成功；
6. 工件、密钥、配置、manifest 和运行日志 SHA-256 完整绑定。

上述门禁只证明该 checkpoint 具备实验部署所需的功能完整性，不将其标记为正式精度或隐私验收通过。

### 5.3 模型结构检查

检查结果分为：

- 支持：允许创建正式任务；
- 实验支持：仅允许创建明确标记的实验任务；
- 不兼容：说明不兼容结构；
- Checkpoint 不完整：列出缺失权重；
- 未知张量布局：列出未被识别的张量。

只有“支持”状态可以进入默认正式流程。检查必须覆盖模型配置、权重索引、张量名称、张量形状、权重格式、专家数量、MTP 层和量化 scale。检查过程中不得执行模型仓库中的远程代码。

### 5.4 本地资源检查

显示：

- Windows 版本；
- CPU 型号与核心数；
- 系统内存总量和可用量；
- NVIDIA GPU、显存和驱动；
- 下载目录、临时目录和输出目录的可用磁盘；
- 网络访问状态；
- 模型预估资源与当前资源的差值。

未检测到 NVIDIA GPU 时允许使用 CPU。资源低于推荐值时显示预计影响。低于硬性磁盘下限时禁止开始，避免生成不完整工件。

### 5.5 创建改造任务

开始前确认：

- 模型和固定版本；
- 改造配置；
- 本地输出、临时文件和密钥备份位置；
- CPU 或 GPU 执行模式；
- 临时磁盘上限；
- 是否在私有分片校验或上传成功后清理对应明文分片；
- 是否自动上传到选定服务器；
- 预计耗时范围；
- 中断恢复和取消后的文件保留规则。

正式执行前必须再次确认。取消确认不产生下载、密钥或输出文件。

### 5.6 任务执行与恢复

流程按分片推进：

```text
下载原始分片
→ 校验来源
→ 本地改造
→ 校验私有分片
→ 保存或上传
→ 按策略清理原始临时分片
→ 记录断点
→ 继续下一分片
```

界面显示：

- 总进度和阶段进度；
- 当前文件、分片、张量和处理块；
- 下载、转换和上传速度；
- GPU 显存、系统内存和磁盘；
- 已运行时间与动态剩余时间；
- 重试次数、最近错误和处理建议；
- 已校验工件数量和字节数。

任务支持暂停、恢复和取消。暂停在当前最小安全处理单元完成后生效。恢复时重新校验已有工件，损坏工件只重做受影响部分。取消任务默认保留已校验私有分片和断点，由用户单独选择清理。

### 5.7 密钥管理

每个改造任务生成独立的模型版本和密钥版本。密钥分为：

- 在线客户端密钥：供隐变智模对话进行 Token 置换和恢复；
- 离线主密钥：供模型改造、结构换钥和恢复；
- 云端运行常量：只包含推理必须且不能直接恢复秘密的信息。

离线主密钥和可迁移备份使用用户设置的独立备份口令加密。备份必须能在另一台 Windows 电脑或重装后的系统中导入，不依赖原 Windows 账户。忘记备份口令时不提供绕过或找回，界面必须在创建时明确提示后果并要求验证一次口令。

当前电脑上的在线密钥可以由 Windows 当前用户保护；需要迁移时必须导出为受备份口令保护的可移植文件。服务器普通资料与凭据分开保存。SSH 密码默认不保存；SSH 私钥默认只记录文件路径，用户主动选择“导入并保护”时才复制到本地加密凭据库。若隧道认证所需密码或私钥口令未保存，对话程序在建立连接时重新提示输入。

### 5.8 服务器管理

一个用户可以保存多个服务器。服务器配置包含显示名称、主机、SSH 端口、用户名、认证方式、sudo 能力和模型目录。

连接后检查：

- Ubuntu 版本和 CPU 架构；
- NVIDIA GPU、驱动和可用显存；
- 系统内存和磁盘；
- Docker 与运行组件；
- 目录权限、端口占用和当前进程；
- 已存在的隐变智模部署；
- 上传带宽和连接稳定性。

第一版正式服务器兼容范围为：

| 项目 | 第一版正式范围 |
|---|---|
| 操作系统 | Ubuntu 22.04 LTS x86-64 |
| 权限 | root，或具备非交互 sudo 权限的普通用户 |
| GPU | 单节点 NVIDIA GPU，正式验收为单 GPU；单节点多 GPU 配置生成标记为实验 |
| 驱动 | NVIDIA 525 或更高，且满足所选运行容器的最低要求 |
| 网络 | SSH 可达；服务器能够访问已配置的软件源和容器镜像源 |
| 正式运行时 | Qwen2.5-0.5B 使用 HF 运行时 |
| 实验运行时 | vLLM、SGLang 和 DeepSeek 多 GPU 配置只生成实验部署，不进入正式验收结论 |

第一版要求服务器已经安装可用 NVIDIA 驱动。服务器没有 Docker 时，仅在能够联网且用户确认后安装。无网络、无 root/非交互 sudo、ARM、其他 Ubuntu 版本和多节点集群不属于第一版正式自动部署范围。服务器检查不得修改服务器；修改必须在用户确认部署后开始。

### 5.9 部署

部署前展示模型需求与服务器实测资源对比。资源不足时明显警告并列出可能后果；用户勾选“了解风险”后可以继续。硬性条件不满足，如 SSH 无法登录、目标目录不可写或 NVIDIA 驱动不可用时，不允许继续。

部署阶段包括：

```text
上传缺失私有分片
→ 校验云端文件
→ 安装或更新运行组件
→ 创建不可变部署版本
→ 启动模型服务
→ 健康检查
→ 私有 Token 往返检查
→ 登记为可聊天部署
```

每个部署记录名称、模型版本、密钥版本、服务器、运行配置、创建时间、当前状态和上一个健康版本。

用户可以：

- 查看状态、日志和资源占用；
- 建立或关闭 SSH 安全隧道；
- 启动、停止和重启；
- 更新运行配置；
- 发布新模型版本；
- 回滚到上一个健康版本；
- 从服务器删除部署；
- 在隐变智模对话中打开。

每个部署默认保留当前健康版本和上一个健康版本。更多历史版本只在用户主动设置后保留。自动清理任何旧版本前必须列出文件和释放空间并获得确认。

删除前列出云端删除对象和预计释放空间。本地密钥、转换工件和其他部署默认不删除。

## 6. 隐变智模对话

### 6.1 可用部署

对话程序只显示同时满足下列条件的部署：

- 部署状态为运行正常；
- 最近一次健康检查通过；
- 本机存在匹配的在线客户端密钥；
- 模型版本与密钥版本一致；
- SSH 隧道已连接或能够建立。

部署中、停止、故障、版本不匹配或密钥缺失的模型显示在“不可用连接”中，并给出原因，但不能发送消息。

SSH 隧道由隐变智模对话按部署独立建立、维护、重连和关闭；隐变智模部署只负责测试连接和保存服务器配置。部署程序关闭不影响已经打开的对话隧道。多个部署分别分配可用本地端口，端口冲突时自动改用空闲端口并在连接详情中显示。缺少认证凭据时由对话程序提示用户输入，不允许静默失败。

### 6.2 多部署与切换

一个用户可以连接多个健康部署。新建对话时必须选择部署。每段会话固定绑定一个部署和密钥版本；切换模型创建新会话，不把旧模型的上下文发送给新模型。

会话历史由客户端保存。每次发送时，客户端使用本地完整会话重新构造 Chat Template，并发送置换后的私有 Token ID；第一版不依赖云端持久会话或跨请求 KV Cache。达到模型上下文上限时保留系统消息和最近的完整用户—助手消息对，从最旧的完整消息对开始移除，不自动摘要。界面必须在发送前提示移除了多少轮，并允许用户取消。重新打开本地历史会话后仍可继续问答，并应用相同上下文规则。

### 6.3 问答

支持：

- Chat Template；
- 中文和英文输入；
- 多轮上下文；
- SSE 流式输出；
- 逐 Token 本地恢复与逐字显示；
- 停止生成；
- 新建、重命名、继续和删除会话；
- 左侧历史会话列表；
- 本地保存会话；
- 每个会话显示使用的部署和模型版本；
- TTFT、TPOT、Token 数和请求状态；
- 清除本地历史。

明文输入在本地应用 Chat Template 和分词。发送内容为私有 Token ID。收到私有输出 Token 后在本地逐个恢复并解码。

### 6.4 隐私过程展示

用户可以开启或关闭隐私轨迹。开启时分阶段显示：

1. 本地原始问题；
2. 原始 Token 示例；
3. 置换后的私有 Token ID；
4. 云端收到的私有输入；
5. 云端返回的私有输出；
6. 本地逆置换；
7. 最终回答。

界面不展示完整在线密钥、完整置换表、离线主密钥或可恢复随机种子。默认关闭隐私轨迹，避免在演示屏幕外泄露不必要信息。

### 6.5 本地数据

会话历史只保存在本地用户配置中，不进入部署任务数据库，不同步到云端。用户可以关闭历史保存。删除会话后从应用历史中移除；“清除全部数据”必须单独确认。

CLI 的技术命令标识为 `yinbian`。以下能力必须同时存在于桌面端和 CLI：

|---|---:|---:|---:|
| 列出推荐模型 | 是 | 否 | 是 |
| 下载或导入模型 | 是 | 否 | 是 |
| 模型结构检查 | 是 | 否 | 是 |
| 本地资源检查 | 是 | 否 | 是 |
| 创建改造计划 | 是 | 否 | 是 |
| 执行、暂停、恢复、取消 | 是 | 否 | 是 |
| 导出与恢复密钥备份 | 是 | 否 | 是 |
| 添加和检查服务器 | 是 | 否 | 是 |
| 上传与断点续传 | 是 | 否 | 是 |
| 部署与健康检查 | 是 | 否 | 是 |
| 启动、停止、重启、删除 | 是 | 否 | 是 |

## 8. 安装、更新与卸载

### 8.1 离线安装包

第一版提供一个 Windows 离线安装包，包含 Windows 客户端运行所需组件，但不包含任何模型权重、Ubuntu 软件包或云端容器镜像。用户下载模型时仍需联网或导入本地模型。第一版自动部署要求 Ubuntu 服务器能够访问配置的软件源和容器镜像源，不支持隔离网络中的云端运行环境安装。

安装程序按 Windows 当前用户安装，不要求为其他 Windows 账户共享密钥。安装包必须发布 SHA-256；正式对外发布版本必须具有可验证的 Windows 代码签名。

安装程序允许选择：

- 程序安装目录；
- 模型与转换工件目录；
- 临时文件目录；
- 是否创建桌面快捷方式；
- 是否将 `yinbian` CLI 加入当前用户 PATH。

安装完成后创建“隐变智模部署”和“隐变智模对话”两个入口。首次启动对话程序且没有健康部署时，引导用户打开部署程序，不显示可输入的空聊天框。

### 8.2 更新

程序更新不得自动修改模型、密钥和部署。更新前显示版本说明并备份本地状态。更新失败时可以恢复旧版本程序和原状态。

模型运行组件更新由部署程序单独管理，不与 Windows 客户端更新混为同一操作。

### 8.3 卸载

卸载时分别询问是否保留：

- 模型与转换工件；
- 在线和离线密钥；
- 服务器配置；
- 部署记录；
- 本地会话历史；
- 日志。

默认保留模型和密钥，避免不可恢复的数据丢失。卸载 Windows 客户端不自动删除云端部署。

## 9. 状态、错误和恢复

用户必须能区分以下状态：等待确认、检查中、下载中、改造中、上传中、校验中、部署中、运行正常、暂停、停止、失败、已取消和已回滚。

每个失败必须提供：

- 失败阶段；
- 人类可读原因；
- 受影响的模型、服务器或部署；
- 是否可重试；
- 重试是否会重复计算或上传；
- 建议处理动作；
- 可复制的诊断编号。

日志不得记录明文问题、完整 Token 流、密钥内容、SSH 密码和私钥内容。

## 10. 安全与隐私边界

1. 在线客户端密钥仅由本地部署/对话进程读取，不传给浏览器页面和云端。
2. 离线主密钥默认不参与在线聊天进程。
3. 云端接口只接受私有 Token ID；明文文本接口默认关闭。
4. 默认通过 SSH 隧道连接云端推理服务，不直接开放公网端口。
5. 高级用户可以配置公网 HTTPS，但必须提供已有域名、有效证书和认证配置；第一版不自动购买域名、修改 DNS 或申请证书。
6. 服务端日志只记录请求 ID、模型/密钥版本、Token 数、状态和耗时。
7. 云端部署包上传前和启动前均执行秘密扫描与完整性校验。
8. 错误密钥、错误模型、越界 Token、损坏响应和中断流必须安全失败。
9. 软件不得把混淆描述为密码学加密，也不宣称抵抗所有恶意服务器。
10. 用户确认资源不足后强制部署，不得绕过密钥、包完整性、驱动、目录权限和身份校验等安全门禁。

## 11. 非功能要求

### 11.1 可用性

- 普通用户可以仅通过桌面向导完成推荐模型部署。
- 每个高成本或外部变更操作前明确确认。
- 首次失败后可以从界面找到恢复入口，不要求使用命令行。
- 同一任务在界面和 CLI 中使用相同名称和状态。

### 11.2 资源

- CPU 模式不因缺少 NVIDIA GPU 而拒绝执行。
- GPU 模式遵守用户配置的显存上限，OOM 后降低处理块重试。
- 临时磁盘达到安全余量前暂停下载并提示用户。
- 状态记录增长不应与权重字节数同量级。

### 11.3 可恢复性

- 应用、系统或网络中断后保留最后一个已校验断点。
- 上传只补传缺失或损坏分片。
- 新版本部署失败时保留旧健康版本。
- 回滚后重新进行健康检查再恢复聊天可用状态。

### 11.4 可访问性

- 所有关键操作可由键盘完成；
- 状态不能只靠颜色表达；
- 错误与进度文本可复制；
- 常用页面在 1366×768 分辨率可正常操作。

## 12. 第一版验收标准

### 12.1 安装

- 在干净的 Windows 10/11 环境离线安装成功；
- 两个桌面程序和 `yinbian` CLI 可以启动；
- 模型和用户数据目录可以自定义；
- 卸载不会默认删除密钥和云端部署。

### 12.2 双入口一致性

- 使用桌面端创建任务后可由 CLI 暂停和恢复；
- 使用 CLI 创建任务后可在桌面端查看完整进度；
- 同一模型、密钥和部署在两个入口中的版本标识一致；
- 桌面端没有 CLI 无法完成的功能。

### 12.3 模型流程

- 推荐 Qwen2.5-0.5B 完成真实下载、结构检查、改造和本地问答；
- OpenSeek 现有真实 checkpoint 完成结构检查和改造回归；
- DeepSeek-V2/V3 缩小 fixture 完成 MLA、MoE、FP8 和 MTP 覆盖检查；
- 未知张量、缺失 scale 和缺失 MTP 权重时拒绝正式转换；
- 中断后恢复不重复处理已校验分片。
- Qwen2.5-0.5B 至少完成一次 CPU 模式完整转换、暂停恢复和结果校验；记录峰值内存与耗时，并与同配置 GPU 结果执行张量误差和固定 greedy 问答一致性比较。

### 12.4 部署流程

- Ubuntu 22.04 x86-64、NVIDIA 525+、root/非交互 sudo 的 SSH 服务器配置可以保存、检查和删除；
- 自动部署流程在符合正式兼容矩阵的受控 SSH 测试环境完成上传、安装、启动、健康检查和回滚；
- 未经过真实公共云 GPU 验收时，发布信息明确标记“真实公共云未验证”；
- 资源不足警告允许用户确认继续，硬性条件失败不能继续；
- 只有健康部署进入对话程序。
- 使用 Qwen2.5-0.5B 完成一次“直接部署”端到端验收：每个原始分片校验后开始改造，每个私有分片校验后立即上传并提交，随后按用户策略清理对应原始分片。
- 直接部署验收记录本地临时目录峰值字节数；除当前输入分片、当前输出分片和配置的缓冲区外，不得同时保存完整原始模型与完整私有模型。
- 在至少一个私有分片提交后主动中断任务；恢复时只转换或上传缺失、未提交或校验失败的分片，已经校验并提交的云端分片不得重复上传。
- 验收证据包含逐分片时间线、本地文件清单、峰值磁盘、云端提交清单、重试记录和恢复前后 SHA-256。

### 12.5 对话

- 可以选择多个健康部署；
- 每个会话固定绑定部署与密钥版本；
- 多轮上下文、SSE 流式输出和逐 Token 恢复正常；
- 回答完成后可以继续输入；
- 历史会话可恢复、继续和删除；
- 隐私轨迹开关不影响实际推理结果。

### 12.6 安全

- 请求、响应、服务端日志和异常日志中不存在测试明文标记；
- 云端包不包含在线/离线密钥、随机种子和原始权重；
- 错误模型或密钥安全失败；
- 默认推理端口不直接暴露公网；
- 安全结论与当前模型、密钥、配置和工件哈希绑定。

## 13. 第一版明确不包含

- 自动购买或关闭公有云实例；
- 阿里云、腾讯云、AWS 等厂商账号 API 集成；
- 自动购买域名、修改 DNS 或申请公网 HTTPS 证书；
- 自动安装或升级 NVIDIA 驱动；
- 隔离网络 Ubuntu 服务器的离线运行环境安装；
- ARM 服务器、Ubuntu 22.04 以外版本的正式支持；
- 多节点自动部署；
- macOS 和 Linux 桌面客户端；
- 手机客户端；
- 任意未知模型的无条件自动适配；
- 在客户不知情时自动量化或替换模型；
- 真实 DeepSeek-V3 完整权重和多节点集群验收；
- 绝对密码学安全保证；
- 将模型权重打包进 Windows 安装程序。

## 14. 命名与迁移

面向用户的名称统一为“隐变智模”：

- 隐变智模部署；
- 隐变智模对话；
- 隐变智模离线安装包。

技术命令标识统一为 `yinbian`。旧 `aloepri` CLI 在一个兼容版本周期内作为别名保留，并显示迁移提示；新文档、配置和工件使用新标识。旧模型和密钥必须能导入，不强制重新转换仅为完成改名。
