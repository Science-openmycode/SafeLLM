1. 论文要求实现的整体流程

AloePri 不只改 prompt，也同步改模型参数和输出坐标。

协变混淆

f̃φΘ(θ)(φX(x)) ≈ φY(fθ(x))
φX(x)=τ(x),   φY(y)=τ(y),   ψY(ỹ)=τ−1(ỹ)

P/Q 扩维

P ∈ ℝd×(d+2h),   Q ∈ ℝ(d+2h)×d,   PQ=Id

权重在模块输入侧乘 Q、输出侧乘 P；相邻模块中的 PQ 相消。每个独立 Q 都必须是同一输入 P 的右逆。

Embedding 与 LM Head

We★=We+αeℰe,   Wh★=Wh+αhℰh
W̃e=ΠWe★Pe,   W̃h=QhWh★ΠT

Attention

论文打印式：

W̃q=QqWqRqkHqkZblock
W̃k=QkWkRqkHqk−1ZblockT
W̃v=QvWvUvo,   W̃o=Uvo−1WoPo

Q/K 的转置打印式一般得到 qZ2kT，不保持内积。v15 使用修正式 q′=qZ、k′=kZ，使 q′k′T=qZZTkT=qkT。实现同时处理 Qwen 的 GQA、rotate_half RoPE 布局、head permutation、2×2 block permutation 和 KV Cache。

FFN 与 RMSNorm

FFN(x)=[SiLU(xWgate) ⊙ (xWup)]Wdown
W̃gate=QgateWgateZ,   W̃up=QupWupHZ,   W̃down=Z−1H−1WdownPdown
论文：κL2=E[‖xP‖2/‖x‖2]
实现：κRMS=E[RMS(xP)/RMS(x)]=√(d/D)κL2,   D=d+2h

v15 manifest 的 paper-expectation 是历史字段名；实际校准量是 20 条固定样本上的经验 RMS 比。

2. 从 prompt 到明文响应

论文文字接口先把混淆 token detokenize 成文本，再由服务端 tokenize；任意 ID 序列不保证 decode→encode 不变。本仓库把可信主接口改为 token ID，模型公式和 τ/τ−1 不变。

客户端 tokenizer
逐 ID 执行 τ
混淆模型 prefill/decode
SSE 返回混淆 ID
τ−1 后 decode
步骤客户端服务端
1加载 tokenizer、tau、inverse_tau、key manifest加载混淆 checkpoint，只保存 model_id/key_id
2prompt → 明文 token IDs—
3每个 ID 计算 τ(id)—
4POST model_id、key_id、input_ids、generation parameters校验 model/key，禁止接收不匹配请求
5—混淆 IDs → Embedding → 24 层 → LM Head → 混淆输出 ID
6逐个接收 SSE token更新同一私有坐标下的 K/V Cache
7inverse_tau(output_id) → 原 tokenizer.decode不记录原文、密钥或完整 token 流

9. 结果

0.5B 上已完成 corrected-paper 模型变换、checkpoint、HF 推理、KV Cache、token-ID 客户端/服务端请求与恢复、MMLU、C-Eval、PIQA、IFEval、HumanEval、空缓存 PUPA VMA、Gate-IA、Attention-IA 代理、IMA、ISA 诊断、TFMA、SDA 代理和 ABBA+BAAB HF 性能。最终验收为 NO-GO：57 项检查中 41 项通过、16 项失败、缺失证据 0 项。

IFEval 四项下降 14.603-18.465 个百分点；HumanEval 从 42/164 降到 0/164。混淆输出包含乱码、重复 token 和非 Python 文本，与整模验证的 19.44% prefill top-1 agreement 相符。token 输入置换、输出 inverse_tau、WSL 受限执行和产物 provenance 均已验证，不能把 0/164 解释为漏恢复或评分器错误。

v17 无噪声与 v16 低噪声的 PIQA 结果显示，论文数值 Embedding/Head 噪声是本次 0.5B 精度损失的主要来源。现有单模型数据不支持把原因归结为参数量；参数量因果检验需要至少一个更大模型作为受控对照。

论文公式的逐项勘误位于 output/pdf/paper_errata/；完整命令和文件表位于仓库根目录 README.md。
