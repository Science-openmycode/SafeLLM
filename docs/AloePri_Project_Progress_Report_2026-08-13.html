2. 论文与 PPT 要求的整体流程

AloePri 的目标不是只把 prompt 变成乱码，而是同时改变输入坐标、模型参数和输出坐标，使私有模型在新坐标下完成同一任务。

2.1 协变目标

f̃φΘ(θ)(φX(x)) ≈ φY(fθ(x))
φX(x)=τ(x),   φY(y)=τ(y),   ψY(ỹ)=τ−1(ỹ)

上式是第 5.1 节的基础协变形式。论文第 6 节和附录 C.6 把可选的在线指数机制 M1 与离线模型混淆 M2 进一步组合：

x★ ∼ M1(x),   pM1(x)(z) ∝ exp[−ε1d(x,z)],   x̃=gx★=τ(x★)
M(x)=(gM1(x), M2(g)) ≡ (M1(gx), M2(g))

因此完整在线输入是“可选 M1 token 扰动，再做秘密词表置换”；默认不启用 M1 时才退化为 x̃=τ(x)。第二个分量 M2(g) 不是随请求传输的数据，而是客户端离线生成并部署到服务器的整套混淆模型权重。

当前实现边界：网页在线链路没有启用 M1。仓库提供了词表不超过 8 时枚举 Sn 的论文精确序列 M1，作为公式 oracle；SDK/CLI 的可扩展 rmdp 模式则按长度 1 的指数机制逐 token 组合，是工程替代，不等同于论文完整序列采样器。

2.2 词表、Embedding 与 LM Head

We★=We+αeℰe,   Wh★=Wh+αhℰh
W̃e=ΠWe★Pe,   W̃h=QhWh★ΠT

Π 是 tau 对应的词表置换矩阵。Embedding 行按私有词表重排，LM Head 输出列同步重排。论文第 5.3 节没有把在线 token 写成矩阵乘法；下面一式是把论文的索引映射 τ(x) 改写成 one-hot 形式后的等价推导，不是论文原式：

X̃=X★ΠT,   X̃W̃e=X★ΠTΠWe★Pe=X★We★Pe

也就是说，网络上传输的仍只是私有 token ID；在服务端做 Embedding lookup 时，它在数学上等价于 one-hot 私有 token 依次乘 ΠWe★Pe。随后隐藏状态继续经过各层的 P/Q、Attention 和 FFN 变换。Embedding 和 Head 噪声分别由 alpha_e、alpha_h 控制；论文方法允许参数校准，不要求加噪后与原模型逐 token 完全相同。

2.3 P/Q 扩维

P ∈ ℝd×D,   Q ∈ ℝD×d,   D=d+2h,   PQ=Id

隐藏维由 d 扩到 D。模块输出侧进入 P，下一模块输入侧进入 Q；无噪声、算子关系正确时，中间的 PQ 抵消。Q 必须与当前输入侧 P 配对，不能把一个右逆无条件复用到所有分支。

2.4 Attention 与 RoPE

W̃q=QqWqRqkHqkZblock
W̃k=QkWkRqkHqk−1ZblockT
W̃v=QvWvUvo,   W̃o=Uvo−1WoPo

工程实现必须适配具体模型的 head 数、GQA 分组和 RoPE 坐标布局。Qwen 使用 GQA 和实际 rotate_half 布局；OpenSeek 的 MLA 还需要处理低秩 Q/KV 投影、解耦 RoPE 与 KV Cache 坐标。论文中会破坏 QK 内积的转置排列式采用单独勘误记录，生产代码使用推导后能保持内积的修正式。

2.5 FFN、RMSNorm、Residual 与 MoE

FFN(x)=[SiLU(xWgate) ⊙ (xWup)]Wdown
W̃gate=QgateWgateZ,   W̃up=QupWupHZ,   W̃down=Z−1H−1WdownPdown

Gate 与 Up 必须使用同步的中间维排列，Down 负责逆变换。Residual 两条支路必须处在同一扩维坐标；RMSNorm 的尺度要按实际 RMS 而不是只按 L2 范数修正。MoE 模型还要同步变换 router 输入、专家编号、共享专家和每个路由专家的 FFN 权重。

9.3 人工复核顺序

  1. 用 Get-FileHash -Algorithm SHA256 检查甲方基线和 evidence index 中的文件。
  2. 打开私有 checkpoint 的 index/manifest，逐项核对源 tensor 到私有 tensor 的覆盖表。
  3. 读取 offline key 中的 P/Q 角色和层号，重算 ||PQ-I|| / ||I||。
  4. 在客户端抓包，确认请求没有 prompt 字段，input_ids 逐项等于 tau(plain IDs)。
  5. 扫描 server package 和日志，确认不存在 online key、原始随机种子、明文或完整 token 流。
  6. 分别运行明文和私有模型，用 inverse_tau 恢复输出；不要用网页显示文本代替网络负载检查。
  7. 最终只以 acceptance JSON 的当前 hash 绑定工件做 GO/NO-GO，不引用旧版本摘要。

11. 最终判断

功能层：Qwen2.5-0.5B 的适用论文机制和产品闭环已经实现，用户可以在本地网页输入问题，客户端把明文转成私有 token ID，服务端用私有模型生成，再由客户端恢复回答。OpenSeek 已把同一产品边界扩展到真实 MoE+MLA checkpoint，源权重转换覆盖为 83/83；MTP 因上游没有发布实际 tensor，不计为已实现。

论文忠实性：代码以论文方法为主线；对无法成立的打印公式和 tokenizer round-trip 假设采用推导后的修正，并单独留有勘误。Qwen 和 OpenSeek 的主网络负载都是 token ID，避免 decode→encode 改写 tau(input_ids)。

性能层：尚不能宣布达到论文/PPT目标。Qwen v47 当前正式工件为 NO-GO，主要差距是 MMLU/C-Eval/PIQA 精度、VMA TTRSR、Gate-IA、known-plaintext 和后端一致性。OpenSeek 目前证明了机制覆盖、产品边界和真实问答链路，但未完成正式精度、完整攻击、三后端和 GPU 性能。

发布结论：现阶段适合继续作为研发演示和验证平台运行；不应把任何 checkpoint 标记为通过全部科研与甲方验收。下一阶段优先把 OpenSeek 的正常回答质量和无噪声等价锁定，再开展正式精度、攻击与性能实验。
