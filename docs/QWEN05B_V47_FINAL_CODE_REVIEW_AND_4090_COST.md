本轮修复：

1. `isolated_score` 原来只检查结果 schema 和 `scoring_only_target_key_access`，无法证明结果属于当前脚本、数据、模型和密钥。现在允许 Windows 路径迁移到 Linux，但所有依赖必须按文件大小和 SHA-256 重新绑定。
2. 增量脚本原来把验收器的退出码 2 当成流水线崩溃。现在退出码 2 表示“报告正常生成、结论为 NO-GO”，只有其他非零退出码才中止流水线。
3. 原上传校验只验证 `.tar.gz`。现在解压后还会验证 4 个 manifest 中声明的每个业务文件，拒绝缺失、篡改、重复路径、路径穿越和多余 manifest。

当前本地验收结果是 `6 PASS / 9 FAIL / 6 NOT_TESTED`。其中 VMA、Gate-IA、known-plaintext 已完成但指标未过；TFMA/SDA 需要正式语料；MMLU/C-Eval/PIQA 需要用统一运行协议重建；IFEval、HumanEval、产品门禁、性能和引擎兼容性尚需服务器补跑。因此，当前状态是“READY TO UPLOAD，正式发布仍为 NO-GO”。

## 2. 为什么不是上传后只跑一次问答

增量验收实际包含至少 36,042 个评测/生成单元，不含攻击候选枚举和引擎冒烟：

| 工作量 | 计算 |
| --- | ---: |
| MMLU 两侧 | 14,042 × 2 = 28,084 |
| C-Eval 两侧 | 1,346 × 2 = 2,692 |
| PIQA 两侧 | 1,838 × 2 = 3,676 |
| IFEval 两侧 | 541 × 2 = 1,082 |
| HumanEval 两侧 | 164 × 2 = 328 |
| 产品问答 | 100 |
| HF 性能请求 | 80 |
| 合计 | 36,042 |

“两侧”是指明文 baseline 和 v47 私有 checkpoint。精度下降、配对置信区间、TTFT/TPOT 劣化都必须由两侧结果计算，不能只运行私有模型。

## 4. IFEval 为什么占 8 小时

IFEval 是时长最大的单项，因为它不是选择题打分，而是 1,082 次自回归文本生成，每次允许最多 1,280 个新 token。v47 candidate 还在 24 层 Attention 的投影中使用 FP64 算术，以保持当前 checkpoint 的函数正确性。

当前 RTX 3060 Laptop 的 v47 candidate 断点工件提供了直接测量：

```text
第一次有效运行：6 条 / 12 分 47 秒
第二次有效运行：2 条 / 5 分 15 秒
合计：8 条 / 18 分 02 秒
平均：135.25 秒/条
3060 全量外推：541 × 135.25 / 3600 = 20.33 小时
4090 candidate 预算：20.33 / 4.52 = 4.50 小时
```

这里对 4090 只采用 4.52 倍加速，没有直接套用显卡厂商的理论 FP32 峰值。原因是运行还包含 Python 调度、tokenizer、逐 token 解码、长度差异、文件断点保存以及消费卡较弱的 FP64 路径。服务器真实速度会由 `stage-timings.tsv` 记录；4.50 小时是预算值，不是已经在该 4090 上测得的事实。

baseline 不执行私有坐标 FP64 投影，但当前统一 FP32/SDPA 协议尚未在该 4090 上实测。3.50 小时包含生成长度差异和首次运行余量。两侧合计按 8.00 小时预留；如果服务器上的平均输出较短，实际会提前结束。

## 5. 28 小时不是预计必须运行 28 小时

费用计划的计算是：

```text
基础任务时长 = 23.25 h
故障重跑准备金 = 23.25 × 20% = 4.65 h
含准备金 = 23.25 + 4.65 = 27.90 h
按整实例小时预留 = ceil(27.90) = 28 h
预算上限 = 28 × 1.80 = 50.40 元
```

因此应区分三种数字：

| 含义 | 小时 | 费用 |
| --- | ---: | ---: |
| 无失败的基础计划 | 23.25 | 41.85 元（数学值） |
| 平台按整小时、约 24 小时结算 | 24 | 43.20 元 |
| 含 20% 重跑准备金的采购上限 | 28 | 50.40 元 |

4.65 小时准备金只在下载失败、环境冲突、OOM 后断点重启或引擎扩展重新安装时使用。所有步骤第一次通过时，不需要为了“用完预算”继续开机，应在证据下载和哈希确认后立即关机。

## 6. 费用中没有计入的项目

用户给出的报价没有数据盘扩容单价和公网出网单价，因此不能将其虚构为 0 元。最终账单为：

```text
最终费用 = 实际实例小时 × 1.80
         + 数据盘 GB × 保留小时 × 页面单价
         + 公网出网 GB × 页面单价
```

当前四个上传归档为 4.337 GiB；解压后 manifest 声明的业务文件约 5.001 GiB。50 GB 数据盘对当前 0.5B 增量实验足够，但运行中间工件、环境缓存和结果需要保留余量，预检要求至少 20 GB 可用空间。

## 7. 服务器执行顺序

```bash
cd /data/AloePri
bash scripts/cloud/bootstrap_qwen05b_cuda121.sh
bash scripts/cloud/run_qwen05b_v47_incremental.sh core
bash scripts/cloud/bootstrap_qwen05b_engines_cuda13.sh
bash scripts/cloud/run_qwen05b_v47_incremental.sh engines
```

`core` 不会重跑 Direct、VMA、Gate/Attention-IA、IMA、ISA 和 known-plaintext；它只补正式 TFMA/SDA、统一协议精度、产品、性能和最终验收。`engines` 只运行 vLLM/SGLang 兼容性并重新生成验收快照。
